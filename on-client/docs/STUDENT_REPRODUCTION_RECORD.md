# 22단계 새 환경 재현 결과 및 버전 기록

> **작성용 기록지입니다.** 빈 항목은 아직 확인하지 않은 값입니다. 실제 새 환경에서 같은 커밋을 실행하고 직접 관찰한 뒤에만 학생 진술로 채우세요. 코드 원문을 읽은 결과, 모의 자료·예제(demo) 실행, 실제 화면 관찰, 실제 연동 결과는 서로 다른 증거입니다. AI의 원문 검토는 새 환경 실행의 증명이 아닙니다.

## 1. 제출 원문과 버전 식별

아래 항목은 **한 번의 최종 검증에 사용한 동일 커밋**을 기준으로 작성합니다. 다른 커밋에서 얻은 결과를 합쳐 한 버전의 성공으로 기록하지 마세요.

| 항목 | 확인값 |
|---|---|
| 저장소 주소(비공개면 비공개로 표시하고 주소는 필요한 제출 화면에만 입력) | 미기록 |
| 브랜치 | 미기록 |
| 검증할 최종 커밋(40자리) | 미기록 |
| 검증 기준 시각(YYYY-MM-DD HH:mm KST) | 미기록 |
| 앱 버전(`on-client/package.json`의 `version`) | 소스에서 확인한 값: `0.2.14` |
| 런타임 계약(`on-client/package.json`의 `engines.node`) | 소스에서 확인한 값: `24.19.0` |
| 실행 도구의 허용·권장 범위 | 문서·스크립트에 적힌 범위: Node.js 22~24 허용, `v24.19.0` 권장 |
| 새 검증 폴더를 만든 방법 | 미기록: GitHub clone / 원본 Git 저장소의 별도 clone / 과제에서 제공한 내보내기 도구 중 실제 방법 기입 |
| 새 검증 폴더의 경로(개인 절대 경로 대신 로컬 별칭 권장) | 미기록 |
| 새 폴더에서 `git rev-parse HEAD`로 확인한 값 | 미기록 |
| 기존 작업 폴더와 기록을 보존했는가 | 미기록 |

앱 버전과 런타임 계약은 프로젝트 파일을 읽어 확인한 값이지, 이 PC에 설치된 버전이나 실행 성공을 뜻하지 않습니다. 현재 프로젝트 파일 목록에는 `on-client/package-lock.json`이 없습니다. 의존성을 바꾸거나 lock 파일을 만들지 말고, 패키지 버전 대조가 불가능하면 해당 단계의 미확인 사유에 그대로 적으세요.

## 2. 원본 보존 및 같은 커밋을 새 폴더에서 받기

1. 원래 작업 폴더를 보존합니다. 먼저 PowerShell에서 원래 Git 최상위 폴더의 상태와 현재 커밋을 확인하고, 아직 기록하지 않은 작업이 있으면 그 내용을 검토합니다. 기존 작업을 덮어쓰거나 지우지 않습니다.
2. 새 검증용 폴더는 원래 프로젝트 폴더와 별도로 만듭니다. 원래 프로젝트 안에 clone하지 않습니다.
3. GitHub에 제출 커밋이 올라가 있고 접근 가능한 저장소라면, 확인한 저장소 주소와 실제 40자리 커밋으로 아래 절차를 사용합니다. 꺾쇠 괄호는 안내용 자리표시자이므로 실제 값으로 바꿔야 합니다.

```powershell
$RepositoryUrl = '<확인한 저장소 주소>'
$Commit = '<제출할 실제 40자리 커밋>'
$CloneFolder = '<원래 폴더와 분리된 새 폴더>'

git clone --no-checkout $RepositoryUrl $CloneFolder
git -C $CloneFolder checkout --detach $Commit
git -C $CloneFolder rev-parse HEAD
git -C $CloneFolder status --short
```

`rev-parse HEAD`가 제출할 40자리 커밋과 정확히 같은지 대조해 기록합니다. `status --short` 결과도 기록합니다. clone·checkout을 이 문서 작성자가 실행한 것은 아닙니다. 비공개 저장소는 공개로 바꾸지 않습니다. Git 인증이 필요한 경우 PC의 승인된 인증 흐름을 사용하고 비밀번호·토큰을 명령, 문서, 캡처, 대화창에 넣지 마세요.

커밋이 GitHub에 올라가 있지 않다면 원래 저장소를 대상으로 한 **별도 폴더 clone** 또는 과제 화면이 안내하는 수료 패키지 내보내기 방법을 사용합니다. 비공개 저장소의 원문 JSON 제출은 과제 화면의 **「비공개 저장소 원문 준비 방법」**과 **`student-source-cli.mjs`의 실제 안내 명령**을 따르세요. 도구·출력 경로는 내 PC에 맞게 지정하고 `--commit`에는 같은 실제 커밋을 사용합니다. 사용자 PC 경로와 커밋을 확인하지 않고 명령을 추측하지 않습니다. 도구가 원문을 묶는 일과 앱 실행·업로드는 별개입니다.

인증·설정 파일을 원래 폴더에서 새 폴더로 무작정 복사하지 않습니다. 이번 과정에 발급되지 않는 SDP 개인 인증서·개인키·접속 토큰을 요청하지 않습니다. 담당자가 별도 승인 환경의 설정을 실제로 안내한 경우에만 그 안내를 따르고, 해당 설정과 자격은 프로젝트·Git·제출물 밖에 둡니다.

## 5. 자료 보존 및 복원 계획

- **원본 보존:** 기존 작업 폴더와 Git 기록은 그대로 둡니다. 새 환경 재현은 별도 폴더에서만 수행합니다. 실행 전에 원래 커밋과 작업 트리 상태를 기록하고, 이미 존재하던 미커밋 변경은 덮어쓰지 않습니다.
- **소스 복원:** 같은 커밋이 GitHub에 있다면 새 폴더에서 해당 커밋을 checkout하여 소스를 다시 받을 수 있습니다. 비공개·미업로드 소스는 과제의 승인된 원문 전달/내보내기 절차를 사용합니다. 원본 폴더를 삭제하거나 reset하여 복원하지 않습니다.
- **설정·자격 보존:** 설정·인증서·키·토큰을 소스 저장소나 제출물에 넣거나 다른 폴더로 무심코 복사하지 않습니다. 비밀값은 백업·근거 자료에도 포함하지 않습니다.
- **실행 자료와 한계:** 이 프로젝트 문서에서 새 환경 재현 결과는 학생이 남기는 진술입니다. 앱 런타임 데이터나 외부 SDP 기록의 백업·복원 성공은 이 기록만으로 보장되지 않으며, 별도의 백업 경로나 데이터 복원 기능이 확인되지 않았다면 `미확인`으로 남깁니다. 운영 데이터 복구가 필요하면 해당 시스템 담당자의 승인된 절차를 따릅니다.
- **증거 보존:** 결과표와 비밀값 없는 근거 자료는 같은 검증 커밋·환경을 식별할 수 있게 보관합니다. 다른 커밋의 성공 캡처를 현재 커밋의 근거로 합치지 않습니다.
